| Endpoint real (rel. a `/api/v1`) | Método | Body de éxito |
| --- | --- | --- |
| `/users/shopping-lists` | GET / POST | `{ lists, total, page, limit }` / `IShoppingListDTO` (201) |
| `/users/shopping-lists/:listId` | GET / DELETE | `IShoppingListDTO` / 204 |
| `/households/:householdId/shopping-lists` | GET / POST | `{ lists, ... }` / `IShoppingListDTO` (201) |

| `/shopping-lists/:listId/duplicates` | GET | `IDuplicateGroupDTO[]` |
| `/users/inventory-items` | GET / POST | `{ items, total, page, limit }` / `IInventoryItemDTO` (201) |
| `/users/inventory-items/:itemId` | GET / PATCH / DELETE | `IInventoryItemDTO` / `IInventoryItemDTO` / 204 |
| `/households/:householdId/inventory-items` | GET / POST | `{ items, ... }` / `IInventoryItemDTO` (201) |

**Rutas de items/movimientos sin prefijo de scope**: la autorización se resuelve desde
la lista/item padre (comentario explícito en ambas rutas). `DELETE` responde **204**.

### Envelope

Igual que en M2: Shopping/Inventory/Households usan respuesta **cruda** en éxito
(`res.json(result.data)`), y errores con el envelope
`{ success:false, error:{code,message,statusCode} }`. El cliente usa `*Raw`.

## T1 — Crear hogar (añadido en este paso)

Motivo: sin hogar el usuario no puede usar ningún endpoint de household (bloqueante).
El resto de flujos de hogar quedan como deuda técnica en APP.

- Domain: `CreateHouseholdInput { name; description? }` + `createHousehold` en el port.
- Data: `CreateHouseholdRequestDto` + `toCreateHouseholdRequest` + impl `POST /households`.
- Presentation: `useCreateHousehold`, `CreateHouseholdScreen` (nombre + descripción
  opcional; al éxito navega a Dashboard), `CreateHouseholdButton` en el selector.
- Navigation: ruta `CreateHousehold`.
- Contrato verificado: `POST /api/v1/households` → **201** `IHouseholdDTO`
  (`{ id, name, description?, ownerId, memberCount, createdAt }`), validado por
  `CreateHouseholdSchema` (`name` 1–255 requerido, `description` ≤1000 opcional,
  `additionalProperties:false`). Error 400 `MAX_HOUSEHOLDS` posible.

> **Desviación de nombres solicitada**: se pidió `dtos/CreateHouseholdDTO.ts` y
> `mappers/householdMapper.ts`. El slice ya tenía `householdDtos.ts` y
> `householdMappers.ts` (plural, convención existente); el DTO y el mapper de request
> se añadieron **en esos archivos** para no fragmentar el slice. Si se prefiere el
> nombre singular, es un rename trivial.
